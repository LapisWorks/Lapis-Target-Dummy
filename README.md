# Lapis Target Dummy

一款 Paper / Folia 训练假人插件：在下界合金块上放置盔甲架，即可把它变成一个**打不坏、不掉耐久、无限刷**的木桩。每次攻击都会在假人头顶弹出伤害数字——数值是**经过护甲、韧性、保护附魔完整减免后**的真实结果，方便你精确对比装备与武器强度。

![版本](https://img.shields.io/badge/Paper%20|%20Folia-1.21.x-blue) ![Java](https://img.shields.io/badge/Java-21-orange) ![构建](https://img.shields.io/badge/ProtocolLib-不需要-green)

## 特性

### 伤害数字
- **真实减伤模拟**：复用原版伤害事件的攻击力（含武器、锋利、力量、暴击、蓄力缩放），再按原版公式依次套用护甲 → 韧性 → 保护魔咒，得到的就是"穿这套甲挨这一下"的实际扣血。
- **动画流畅且零开销**：上升 + 淡出全部由客户端插值完成，每个数字只发 2~5 个数据包，没有任何逐刻运行的任务；没人训练时插件完全静默。
- **深色底板**：半透明背景板常驻，白天夜晚都看得清。
- **自动避让**：新数字沿向日葵螺旋寻找空位，不会叠成一坨。
- **受击无敌帧**：模拟原版 0.5 秒受击冷却——连点时低伤直接吞掉，重击只显示超出的差值，和打真生物的手感一致。
- **DPS 总结**：停手 1 秒后弹出一条青色 `DPS X.X`，汇总刚才一轮输出的秒伤。
- **类别符号**：☠ 亡灵 / ≋ 海洋 / ⚔ 灾厄 / ⚘ 节肢，一目了然当前假人模拟的是什么生物。

### 类别模拟
盔甲架的 `EntityCategory` 在原版里不可修改，因此插件自行模拟了四类"对种附魔"：

| 主手放置 | 模拟类别 | 生效附魔 |
|---|---|---|
| 腐肉 | 亡灵 | 亡灵杀手 (Smite) |
| 海龟壳 | 水生 | 穿刺 (Impaling) |
| 不祥旗帜 | 灾厄 | 灾厄克星? 见下方说明 |
| 蜘蛛眼 | 节肢 | 节肢杀手 (Bane of Arthropods) |

> 不祥旗帜在 1.21.x 中不是独立物品，插件通过物品名称翻译键 + 图案特征识别，手工合成的不祥旗帜同样有效。

### 装备管理
- **右键假人**直接打开 9 格装备界面，6 个槽位（头盔/胸甲/护腿/靴子/主手/副手）可以放**任意物品**——包括原版盔甲架放不进去的。
- 多人同时编辑同一假人也不会复制或丢物品：每次点击都以假人身上的真实装备为准，所有打开该假人界面的玩家视图同步刷新。
- 原版的盔甲架手动交换已被禁用，装备只能通过界面改动。

### 创建与拆除
- **创建**：把盔甲架放在下界合金块上（基块可在配置中更换）。
- **拆除**：任选其一——
  - 空手潜行攻击假人；
  - 直接挖掉下面的基块（盔甲架和全套装备一起掉落）。

## 安装

1. 服务器要求 **Paper 1.21.1 或更高**；兼容分支 Purpur、Folia 均可（Folia 支持自 v1.1 起，所有任务走实体区域调度器）。
2. 把 `Lapis-TargetDummy-<版本>.jar` 放进 `plugins/` 目录，重启服务器。
3. 首次启动会生成 `plugins/LapisTargetDummy/config.yml`，全部选项都有中文注释。

不需要 ProtocolLib，不需要依赖任何前置插件。

## 构建

```bash
./gradlew build
```

产物位于 `build/libs/Lapis-TargetDummy-1.0.jar`。

- Java 21 工具链（缺失时 Gradle 会自动下载）
- 仅依赖 `paper-api:1.21.1-R0.1-SNAPSHOT`（compileOnly）
- 单元测试覆盖了护甲减免公式的 11 个用例：`./gradlew test`

> 项目使用 Gradle Wrapper 构建；若你的环境已装有 Gradle 9+，也可以直接用系统 Gradle。

## 设计说明

- **状态全部存在实体 PDC 里**：没有数据文件、没有启动扫描，启用/重载都是 O(1)；假人随区块存档，重启即恢复。
- **伤害永远被取消**：假人不掉血、不受击退、不掉装备，武器也不掉耐久；唯一的例外是 `/kill` 与掉出虚空，保证管理员工具照常可用。
- **Folia 兼容**：没有全局主线程可依赖——所有延迟任务（数字动画与到期回收、DPS 总结、放置确认、拆除延迟、菜单刷新）都通过**实体自身的调度器**执行，自动落在拥有该实体的区域线程上；共享状态使用并发集合，计时用 `nanoTime` 而非全局 tick 计数。在 Paper 上实体调度器退化为普通主线程任务，行为不变。
- **性能**：没有常驻任务。每个伤害数字只安排 3~5 次一次性延迟写（动画 + 到期自删），无人训练时插件完全静默。

## 局限性

插件在伤害事件之后手动补算了盔甲减伤，因此有些东西是模拟的、有些是不管的：

### 会正确生效

- **自定义护甲值**：护甲与韧性从物品的属性修改器读取（无修改器则退回材质默认值），指令或数据包给装备加的 `armor` / `armor_toughness` 自动计入；
- 武器侧的一切原版加成（附魔、药水、暴击、蓄力缩放）已由服务端算入基础伤害，直接复用；
- 盔甲上的保护 / 爆炸保护 / 弹射物保护 / 火焰保护（专属变体按原版规则计双倍 EPF）；
- 重锤的**密度**（加伤发生在事件之前，天然包含）；
- 无视护甲的伤害类型（魔法、凋零、龙息、音波炮、荆棘伤害等）按原版 `#bypasses_armor` 标签处理。

### 不会模拟

- **破甲 (Breach)**：它作用于受击方的护甲效率公式，暂未计入；
- 盔甲的**荆棘反伤**：假人不会反弹伤害（仅把"受到的荆棘伤害"当作无视护甲处理）；
- **摔落缓冲**等非保护系的减伤附魔（且摔落属于环境伤害，默认关闭显示）;
- **数据包新增的自定义附魔**：只识别原版注册表中的附魔，第三方"高级保护"之类不会生效；
- 属性**乘法**修饰符（`multiply` / `add_scalar`）：只累加加法修饰符——原版盔甲不使用乘法，但极端自定义物品可能少算；
- 副手举盾格挡：盔甲架本身不会格挡。

> 类别附魔（亡灵杀手 / 节肢杀手 / 穿刺）是插件手动模拟的，因为盔甲架的实体类别恒为 NONE——这正是本插件存在的理由之一。
